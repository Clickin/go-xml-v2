# Streaming XML comparison on Windows amd64

Measured on an Intel Core i5-13600K, using this tree at `bd5149100704087efd1edf06bfb7d6956aa636ac` (Go 1.28 devel, `GOEXPERIMENT=xmlv2`, `GOAMD64=v1`, `CGO_ENABLED=0`), Woodstox 7.2.0 with StAX2 API 4.3.0 on Temurin Java 25.0.1, and quick-xml 0.42.0 with Rust 1.99.0 and `cargo build --release`. `GOMAXPROCS=8`; parsing is single-threaded. Java heap is fixed at 512 MiB. The corpus is the same 16,777,093-byte ASCII catalog as the parent benchmark, SHA-256 `2DACA51670D9EA14E50F87BB88B5EC80D0F6BA0B384B3542E43AC153ECA913D3`.

All implementations load the file before timing and consume start and end local names, attribute local names and decoded values, and decoded text. They compute the same sum of lengths, 12,651,578. A separate ASCII check containing an escaped attribute, escaped text, a numeric reference and an empty element produced the same checksum of 23 for all implementations. Length-sum checks do not prove full semantic equivalence. Woodstox DTD support is disabled; quick-xml does not perform all the same well-formedness and namespace checks as the other parsers. Java counts UTF-16 units; Go and Rust count UTF-8 bytes. The tested corpus is ASCII and does not exercise namespace declarations, DTDs, multibyte characters, or many other XML features. These numbers are specific to this document and workload.

Each implementation is started in three processes, alternating implementation order. Each process runs eight warmups followed by ten measured iterations; input creation and JVM startup are excluded. `samples.csv` stores 90 measurements, and `summary.csv` reports medians and ranges across each implementation's 30 iterations. Iterations within one process are not independent, so the range is descriptive and is not a confidence interval. No allocation comparison is claimed. This custom workload constructs a new decoder each iteration; it is not directly comparable to the earlier Go benchmark, which resets an existing decoder and ran at a different time.

To reproduce, first build the repository toolchain and run the parent `run.ps1` to generate the corpus. Set `GOROOT` to the repository root, `GOEXPERIMENT=xmlv2`, `GO111MODULE=off`, `CGO_ENABLED=0`, and build `src/main.go` into `pkg/comparison-go.exe` using `bin/go.exe build`. Build the Java file into `pkg/comparison-java` with `javac` and Woodstox/StAX2 on its classpath. Build the Rust project with `cargo build --release --locked` and `CARGO_TARGET_DIR` set to `pkg/comparison-target`. The `run.ps1` script contains the local jar paths and should be adjusted on other machines. It executes the processes serially, checks the checksum, and overwrites the CSV files.
